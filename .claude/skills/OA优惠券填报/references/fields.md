# 优惠券 OA 填报字段 schema

> schemaVersion: `coupon-oa-p1-fields v1.0`
> 依据：PRD v1.2 P1、[OA 表单截图](../../cases/202609240455/screenshots/10-oa-case-202609240455.png)、[案例 202609240455 分析](../../cases/202609240455/README.md)。
> 变更本 schema 须由业务与流程 Owner 确认并递增版本号；底稿与 fields.json 必须记录所用版本。

## A. 表单字段（与 OA 页面顺序一致）

| # | key | 表单字段 | 类型 | 必填 | 允许值 / 格式 | 来源 |
|---|-----|---------|------|------|---------------|------|
| 1 | `department` | 部门 | 文本 | 是 | 组织架构路径，如 `拍拍业务部-平台业务部-寄卖业务部` | 业务员或截图 |
| 2 | `applicant` | 申请人 | 文本 | 是 | 人名，如 `黄慧兰` | 业务员 |
| 3 | `applicationType` | 申请类型 | 单选 | 是 | 当前仅 `优惠券申请` | 固定值 |
| 4 | `businessMode` | 业务模式 | 单选 | 是 | 已确认：`寄卖`；其余取值待业务 Owner 确认 | 业务员 |
| 5 | `activityName` | 活动名称 | 文本 | 是 | 自由文本，案例：`9.30-10.10寄卖苹果手机优惠券申请` | 业务员 |
| 6 | `activityBackground` | 活动背景 | 长文本 | 是 | 建议包含：券档列表、预计券率、机型/品类策略 | 业务员 |
| 7 | `overDeduction` | 是否超扣点 | 单选 | 是 | `是` / `否` | 业务员 |
| 8 | `estimatedGmv` | 预估GMV | 金额（元） | 是 | 正数；统一以**元**记录，OA 页面以「万元」展示（如 349.65 万元 = 3496500 元） | 业务员；须通过口径硬校验 |
| 9 | `estimatedCost` | 预估费用 | 金额（元） | 是 | 正数，同上口径 | 业务员；须通过口径硬校验 |
| 10 | `roi` | ROI | 数值 | 是 | 通常 = GMV ÷ 费用 取整（案例 35）；留空则派生 | 派生 / 业务员 |
| 11 | `channels` | 配置渠道 | 多值文本 | 是 | 以「；」分隔，案例：`京东渠道；严选APP及小程序` | 业务员 |
| 12 | `activityStartAt` | 活动开始时间 | 日期 | 是 | `YYYY-MM-DD` | 业务员 |
| 13 | `activityEndAt` | 活动结束时间 | 日期 | 是 | `YYYY-MM-DD`，须 ≥ 开始日期 | 业务员 |
| 14 | `durationDays` | 时长(天) | 数值 | 派生 | = 结束 − 开始 + 1（案例 11） | 派生，冲突时报告 |

## B. 附件字段（三份材料）

| # | key | 表单字段 | 格式 | 必填 | 校验 | 来源 |
|---|-----|---------|------|------|------|------|
| 15 | `calcImage` | 请上传具体满减测算图片 | png/jpg/jpeg | 是 | 只登记路径/大小/哈希；**不解读内容** | 业务员文件 |
| 16 | `couponTable` | 请上传配券信息表（按模板填写） | .xlsx | 是 | 按 SKILL.md 第 3 步解析校验；标准模板见 `assets/templates/` | 业务员文件 |
| 17 | `productWhitelist` | 请上传商品明细白名单 | .xlsx | 是 | 两种模式：标准单列 ID 名单；券档多工作表明细（每表绑定一个券档、含 SKUID 主键） | 业务员文件 |

## C. 派生与核对项（不进 OA 表单，进 validation-report）

| key | 说明 |
|-----|------|
| `couponRows` | 配券信息表解析出的券批次行（渠道 × 券档），含 面额/限额/张数/费用/GMV/ROI |
| `aggregations.perChannel` | 按渠道合计 预计费用/预计引入GMV/ROI |
| `aggregations.allChannels` | 全渠道合计 |
| `aggregations.oaMatch` | OA 数值命中「单渠道」或「全渠道」或「不一致（需业务员选择口径）」 |
| `whitelistStats` | 每工作表：非空行数、SKUID 去重数、链接状态分布、跨档重复 SKUID 数 |
| `openIssues` | 待确认清单（口径、模糊字段、重复 SKU 处置等） |

## 待确认（继承自案例 §6，未确认前只报告不拦截）

1. OA 预算口径：单渠道基准 vs 全申请合计。
2. 「总申请数量」公式中固定乘数 3 的含义。
3. 「预计券率」「预计领用率」「预计使用率」的口径关系。
4. 券档 ↔ 机型/价格段 ↔ 白名单工作表的正式映射。
5. 多工作表明细白名单是否为正式长期模板。
6. 链接状态为空、SKU 跨档重复的处置规则。
