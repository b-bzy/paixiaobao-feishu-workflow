# OA 优惠券提报：边缘规则清单

> 本清单用于业务 Owner、流程 Owner 和模板 Owner 逐项确认。未确认项必须停在“待业务确认”，不得由系统或 AI 猜测处理。
> **定位**：综合 Skill 的本地评审与拟议飞书运行时规则；不是当前 Bot 已上线行为或原生 OA 提交授权。
> **字段参考**：[fields.md](fields.md)。

## 1. 材料接收

| 场景 | 业务处理 |
| --- | --- |
| 未上传配券表 | 阻断；提示上传 `.xlsx` 原始配券表 |
| 未上传白名单 | 阻断；白名单为本期必传材料 |
| 未上传黑名单 | 显示“本次无黑名单”，要求 owner 显式确认；确认前不能生成或提交 |
| 已填充标准配券表无法完整生成图片 | 当前 OA 表单中该附件为必填；阻断第二次确认。只能从同 revision 已验证标准配券表渲染，不能上传或使用原始源表替代。 |
| 上传黑名单但文件打不开/为空/无法映射 | 视为无效文件，不得自动当作无黑名单 |
| 文件同名或顺序混乱 | 系统先按 Sheet、表头、单元格类型和样例给出角色候选；文件名只能辅助判断 |
| 源表结构未知 | 系统识别 Sheet、表头、说明行、数据行、字段/ID 候选和附加列；不要求预先提供格式说明 |
| 同一角色上传多个文件 | 不静默替换；要求选择采用哪份，或确认新文件替换旧文件 |
| 用户上传图片/PDF/压缩包作为三源表 | 首期不作为配券表/白黑名单接受；要求重新导出 `.xlsx` |
| 文件超过已发布大小、行数或 Sheet 上限 | 阻断，走人工处理 |

## 2. 配券表字段来源

| 场景 | 业务处理 |
| --- | --- |
| 配券表能唯一识别字段 | 使用配券表值并记录来源 |
| 配券表没有 OA 必填字段 | 只追问缺失字段，不让业务员重填完整表单 |
| 一个字段存在多个合理来源列/单元格 | 展示候选、样例和影响，由 owner 确认 |
| 配券表值与补充内容冲突 | 显示差异；显式覆盖必须说明原因 |
| 配券表公式无可靠结果 | 不将公式文本当业务值；要求提供可靠值或修正文件 |
| 活动 ID、批次 ID、putKey、领券链接为空 | 正常，标记为建券后回填；禁止编造 |
| 未登记券型或模板版本 | 阻断，不能用“最接近模板”静默生成 |
| 折扣券公式存在多种业务情形 | 选择已发布计算规则；未发布则阻断 |
| 模板支持的券档多于本期实际券档 | 记录未配置券档为 `info`；只要本期每个券档可唯一映射，就不是模板错误 |
| 券档没有已配置型号/券额策略 | 展示 `unconfigured_coupon_tier` 信息提示；不得由 AI 补造策略，不生成缺失字段，也不使文案候选降级或阻断标准附件。 |

## 3. 白名单与黑名单

| 场景 | 业务处理 |
| --- | --- |
| 白名单/黑名单 ID 维度不同 | 阻断；不能计算交集或生成标准名单 |
| ID 维度不清楚 | 展示 SKU / SPU / 商家 ID 候选，要求确认 |
| 空单元格 | 阻断，回显 Sheet/行/列和样例 |
| 一个单元格多个 ID | 阻断；要求源文件拆成一格一个 ID |
| 公式、外部链接、数值型导致前导零风险 | 阻断；要求业务员提供文本格式源文件 |
| 同一名单内重复 ID | 按已发布业务策略处理；策略未发布时不得静默去重 |
| 白名单与黑名单没有重叠 | 正常，进入生成 |
| 一个券档无法唯一映射到名单模板 Sheet | 展示券档和可用 Sheet，要求确认；不能按 Sheet 顺序猜测 |
| 白名单与黑名单有重叠 | 展示完整冲突清单；owner 选择白名单优先、黑名单优先或改源表 |
| 重叠决定后任一名单变更 | 原决定、生成表和最终确认全部失效，重新确认 |
| owner 确认无黑名单 | 最终确认页必须显示“无黑名单”；OA 不上传伪造的空黑名单附件 |

## 4. OA 字段与计算口径

| 场景 | 业务处理 |
| --- | --- |
| 活动点位与优惠比例是否相同未确认 | 作为待确认字段，不自动映射 |
| 活动开始/结束时间与可领/可用时间关系不明确 | 不直接互填；由已发布映射或 owner 补充 |
| 结束日期早于开始日期 | 阻断 |
| 时长与日期不一致 | 使用日期派生值并要求确认差异 |
| 预计费用与模板公式结果不同 | 展示来源值、重算值和公式；必须确认后才可进入最终页 |
| 预估 GMV、费用或 ROI 无法计算/为零/负数 | 阻断 |
| 单渠道与全渠道汇总口径不同 | 最终确认页明确显示采用口径；未决定则阻断 |
| 超扣点为“是”但没有原因 | 阻断 |
| 超扣点默认“否” | 记录为 `defaulted_pending_unified_confirmation`；在最终统一确认中展示并审计，不新增独立确认字段；改为“是”时原因必填。 |
| OA 审批定义/控件/枚举已变化 | 阻断，重新核对并确认 OA 预填 |

## 5. 澄清循环、两次确认与修改

澄清循环可以多次出现，但不构成额外确认。业务确认只有两次：**来源确认**与**最终确认**。

| 场景 | 业务处理 |
| --- | --- |
| 来源确认前 | 只接收、解析和反馈；不得生成可提交 OA 附件或原生 OA |
| 来源确认后修改字段、文件、列映射、无黑名单确认或重叠决定 | 创建新 revision；旧标准文件和最终确认卡失效 |
| 最终确认页 | 必须展示 OA 字段、标准附件、黑名单状态、重叠决定、计算结果、警告和 hash |
| 非 owner 点击确认 | 拒绝；只有当前 task owner 可以确认/发起 |
| 旧卡片或重复点击 | 提示使用最新卡；不得复用旧 revision 发起 OA |
| R2 draft-only 的最终确认 | 创建/更新系统草稿、冻结产物并交接既有 OA 测试稿；禁止原生 OA 创建 |
| R3/R4 的既有明确“发送”动作 | 服务端创建原生 OA 并立即回读；不再展示第三次确认 |
| 创建结果未知 | 显示“提交状态未知”，只能查询/人工核验，禁止盲目重提 |
| 创建成功但回读差异 | 标记需人工复核，返回 OA 链接和差异；不得假装成功 |

## 6. 审计、权限与数据边界

| 场景 | 业务处理 |
| --- | --- |
| 原始源文件 | 只读保留，不能被覆盖或直接作为标准 OA 附件 |
| 标准生成文件 | 记录模板版本、生成规则、行数与 SHA-256；仅确认后的冻结版本可上传审批附件 |
| 部门/申请人 | 飞书运行时以最终确认人的身份为准；本地模式只能标为待核对 |
| AI 提取 | 只可提供候选映射和缺失项；不能决定冲突、名单优先级、模板或提交 |
| 外部写入 | 标准附件上传、系统草稿和原生 OA 创建必须有 owner、revision、幂等键和回读记录 |
| 文件与真实业务数据 | 仅在授权环境处理；共享测试只使用脱敏 fixture |
| 运行阶段/allowlist/kill switch 缺失 | native-submit 必须 fail closed，卡片隐藏不能代替服务端授权 |

## 7. 当前必须由业务方确认的项目

1. 首期支持的券型及每个券型的正式配券模板；
2. 白名单/黑名单正式模板、Sheet 名、列头、ID 维度、行数上限和重复策略；
3. “活动点位(%)”与配券模板“优惠比例”的关系；
4. 配券表与 OA 的渠道、活动日期、业务模式、超扣点等字段映射；
5. 折扣券不同费用公式的适用条件和舍入规则；
6. 白黑名单重叠时允许的业务选项及是否允许“保留两边”；
7. 已填充标准配券表截图的 OA 图片控件、完整渲染规则、保留期限和审计字段；
8. 部门默认值和业务员可修改范围；
9. OA 预估 GMV、费用使用单渠道还是全渠道汇总的业务口径；
10. 试点文件保存期限、可见范围、运行 Owner 和 `SubmissionUnknown` 对账责任。
