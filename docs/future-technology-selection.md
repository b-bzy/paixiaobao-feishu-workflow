# 后续技术选型决策

> 状态：待决策，持续更新
> 创建日期：2026-09-28
> 最近更新：2026-10-08
> 适用阶段：受控内网试点后的生产化评估与正式生产阶段；内网试点例外见 ADR-0006。
> 当前基线：[爱回收飞书工作流 POC 与优惠券内网试点架构基线 v1.1](architecture-decision.md)
> 规模前提：开发 POC 不超过 10 人；优惠券内网试点仅限批准 allowlist；后续首批正式上线人员约 30 人。

## 1. 文档目的

本文件用于评估、比较和记录 POC 之后的技术选型。它不代表任何候选技术已经被采用，也不替代已接受的 ADR。

当前 POC 已采用的组合是：飞书交互层、妙搭管理员控制面、Vercel Hobby（免费开发测试环境）上的 Nitro/Node.js 服务与飞书 Base。正式上线前需要根据真实员工规模、企业采购、网络可用性、数据驻留、合规和运维能力，决定付费正式版本或其他正式执行面及其依赖资源。

## 2. 已确定且不重新选型的架构边界

后续选择产品或供应商时，必须保留以下边界；如果需要改变其中任何一项，必须先创建新的 ADR：

1. 飞书仍是员工发起、审批和结果通知的主要业务入口。
2. 正式目标仍采用标准 HTTPS callback：同步路径只做验证、去重、可靠接收和快速响应，耗时工作异步处理。经 [ADR-0006](adr/0006-use-managed-long-connection-bridge-for-internal-coupon-pilot.md) 接受的企业托管 WebSocket bridge 仅是时间受限的优惠券内网试点例外，不能取代此目标。
3. 管理员配置体验与任务执行面分离；妙搭页面权限不能替代后端鉴权。
4. 权限、审批路径、状态转换、幂等和最终业务写入由确定性代码控制，AI/Agent 不得绕过这些规则。
5. 已发布配置、流程实例、审批、事件和审计只能有一个权威数据源；禁止 Base、妙搭数据库和主数据库长期三方双写。
6. 正式运行时不能依赖个人电脑、个人登录、函数本地磁盘、进程内内存或进程内队列保存关键状态。试点 bridge 也必须运行在企业托管常驻环境，并具有持久 outbox、认证、去重、监控和明确退出条件。

这些边界的决策背景见 [ADR-0001](adr/0001-adopt-phased-hybrid-architecture.md)、[ADR-0002](adr/0002-use-http-callback-as-event-ingress.md) 和 [ADR-0003](adr/0003-separate-miaoda-control-plane-and-vercel-execution-plane.md)。

## 3. 何时启动选型

满足下列任一条件时，项目负责人应创建或更新本文件中的具体决策记录：

- POC 已完成验收，准备向真实员工或部门试点开放。
- 需要保存真实财务、客户或其他受监管数据。
- Vercel 的中国大陆访问质量、数据驻留、可用性或企业合规不满足目标。
- 需要可靠的异步任务、重试、死信、事件重放、附件处理或 AI 长任务。
- 企业已有云账号、数据库、消息队列、日志平台、采购或安全标准要求接入指定产品。
- 需要接入 OA、ERP、财务、邮件、数据仓库或其他内部系统。

在未完成相应决策前，不得将候选架构描述为已上线或已承诺的生产方案。

## 4. 统一评估维度

每项选型至少从以下维度进行比较，并保留证据链接、测试数据或企业确认记录：

| 维度 | 要回答的问题 |
|---|---|
| 合规与数据驻留 | 数据处理地域、访问控制、审计、备份和保留策略是否符合企业要求？ |
| 网络与可用性 | 中国大陆访问、飞书回调成功率、延迟、故障恢复和扩缩容是否满足目标？ |
| 企业适配 | 是否使用现有企业账号、网络、采购合同、运维体系和安全基线？ |
| 可靠性 | 是否支持持久化、幂等、重试、死信、备份、恢复和可观测性？ |
| 扩展性 | 能否支持更多 Skill、事件量、附件、外部系统和 Agent 任务？ |
| 安全性 | 身份传递、最小权限、密钥管理、网络隔离和日志脱敏如何实现？ |
| 迁移复杂度 | 对现有 HTTP 合同、领域代码、数据模型和运维流程的改动有多大？ |
| 成本与运维 | 固定成本、按量成本、人员能力、告警、值班和供应商锁定如何评估？ |

## 5. 待决策技术项

### 5.1 国内事件网关与计算托管

| 内容 | 待决策项 |
|---|---|
| 决策目标 | 为正式飞书 HTTP 回调和业务 API 选择满足国内网络、合规与弹性要求的托管方式。 |
| 候选方向 | 腾讯云 SCF + API 网关、阿里云函数计算 FC、企业容器/Kubernetes、企业已有后端平台。 |
| 当前状态 | 开发测试继续使用 Vercel Hobby（免费版）；腾讯云候选项均未采用。 |
| 所需证据 | 企业首选云和采购约束、飞书回调压测、网络连通性、地域与数据要求、故障演练、成本测算。 |
| 决策触发 | 部门试点、真实数据接入，或 Vercel 不满足网络/合规要求。 |

选择时应保持飞书 HTTP 回调协议和领域服务接口可迁移；网关只承担校验、快速响应、去重、入队和转发，不执行耗时 AI 推理。

### 5.2 业务 Worker 与运行时

| 内容 | 待决策项 |
|---|---|
| 决策目标 | 为异步工作流、外部系统调用、附件处理和 Agent 任务选择可恢复的执行方式。 |
| 候选方向 | 云函数异步任务、容器化 Worker、企业任务平台；继续使用 TypeScript/Node.js 领域服务。 |
| 当前状态 | POC 使用 Nitro/Node.js 的简化同步处理；没有已选定的持久化 Worker。 |
| 所需证据 | 任务时长与并发、超时限制、重试语义、部署方式、失败恢复、运维与成本。 |
| 决策触发 | 引入长耗时任务、AI、OCR、外部系统或需要可靠重试时。 |

### 5.3 主数据库与数据迁移

| 内容 | 待决策项 |
|---|---|
| 决策目标 | 为已发布配置、模板快照、流程实例、审批、事件、审计和通知选择唯一事实源。 |
| 候选方向 | 企业批准的 PostgreSQL、企业 MySQL 或已有合规关系型数据库。 |
| 当前状态 | POC 使用飞书 Base；主数据库尚未选择。 |
| 所需证据 | 数据分级、地域、事务与唯一约束需求、备份恢复、访问模型、容量、迁移与对账方案。 |
| 决策触发 | 多 Skill、部门试点、正式数据接入或 Base 无法满足事务/查询需求时。 |

Base 可以在迁移后作为只读运营视图或停止正式写入；不应与妙搭数据库和主数据库长期同时写入相同的正式业务状态。

### 5.4 持久化队列、重试与死信

| 内容 | 待决策项 |
|---|---|
| 决策目标 | 保证回调可靠接收后，耗时任务可异步执行、重试、追踪和人工补偿。 |
| 候选方向 | 企业已有消息队列、腾讯云 TDMQ、阿里云消息队列或与所选云/运行时兼容的托管队列。 |
| 当前状态 | 未选型；禁止使用进程内队列充当正式可靠机制。 |
| 所需证据 | 投递语义、重复处理策略、可见性超时、死信、重放、可观测性、成本与权限模型。 |
| 决策触发 | 回调需在时限内确认、需要重试/死信，或任务超过同步处理能力时。 |

队列的“至少一次”投递不取代业务幂等：事件表唯一约束、业务幂等键和审批状态条件更新仍须由应用与数据库共同保证。

### 5.5 对象存储、日志与监控

| 内容 | 待决策项 |
|---|---|
| 决策目标 | 安全保存附件、提供回调与任务可观测性，并支持审计、告警和故障排查。 |
| 候选方向 | 所选云的对象存储和日志服务，例如腾讯云 COS/CLS、阿里云 OSS/SLS，或企业已有平台。 |
| 当前状态 | 未选型。 |
| 所需证据 | 附件数据分类、加密、访问授权、生命周期、日志脱敏、保留期、告警和值班要求。 |
| 决策触发 | 接入真实附件、审计合规要求或部门试点监控要求时。 |

### 5.6 AI/Agent 与密钥管理

| 内容 | 待决策项 |
|---|---|
| 决策目标 | 在不破坏审批、权限和审计边界的前提下，选择模型接入、Agent 执行与 Secret 管理方式。 |
| 候选方向 | 企业批准的模型供应商或 AI 平台、受控 Agent Runtime、云端密钥服务。 |
| 当前状态 | 未选型；当前 POC 不依赖 AI 完成审批决策。 |
| 所需证据 | 模型允许范围、数据出境与脱敏、Token 成本上限、工具授权、审计、降级和人工兜底策略。 |
| 决策触发 | 需要意图识别、OCR、分类、知识检索或多 Agent 协作时。 |

## 6. 候选组合与成本假设

### 6.1 当前规模的容量判断

为便于比较，暂按每位参与者每月最多发起约 10 个报销流程估算：POC 不超过 10 人，即不超过约 100 个流程/月；首批正式上线约 30 人，即不超过约 300 个流程/月。

这个规模对 API 调用和业务吞吐量而言仍然很低：不需要因为“30 人”本身引入 Kubernetes、专用高吞吐消息集群或高规格数据库。正式技术选型的主要驱动应是数据合规、可靠性、审计、备份、网络与企业现有基础设施，而不是 QPS。

### 6.2 候选组合

下表仅用于建立评估起点，不是采购结论。所有价格、容量和供应商功能都必须在决策时按实际账号、地域、合同和时间重新验证。

| 组合 | 候选技术组合 | 对当前规模的适用判断 | 当前状态 |
|---|---|---|---|
| A：开发测试 | 妙搭 + Vercel Hobby（免费版）+ 飞书 Base | 适合 ≤10 人、约 100 个流程/月的开发验证；仅使用测试数据，不向正式员工开放。 | 已采用用于开发测试 |
| B：Vercel 正式版本 | 妙搭 + Vercel Pro + 托管 PostgreSQL + 轻量持久化队列 | 适合约 30 人、约 300 个流程/月，且企业允许继续使用 Vercel 的内部上线；提供事务、唯一约束和可靠异步能力。 | 待评估 |
| C：腾讯云正式执行面 | 妙搭 + 腾讯云 API 网关/SCF + TDMQ + 企业 PostgreSQL + COS + CLS | 按同一规模假设，适合约 30 人、约 300 个流程/月；用于需要国内访问、数据驻留、企业采购或合规保障的场景。 | 待评估 |

### 6.3 成本预估

所有组合均按相同的流程量方法估算：每位参与者每月最多约 10 个报销流程。即 POC 不超过 10 人为不超过约 100 个流程/月；首批正式上线约 30 人为不超过约 300 个流程/月。

| 组合 | 人数与流程量假设 | 新增基础云资源粗略预算 | 说明 |
|---|---|---:|---|
| A：开发测试 | ≤10 人，≤100 流程/月 | ¥0/月 | 使用 Vercel Hobby 免费版，复用现有妙搭与飞书权益；仅用于测试数据和开发验证。 |
| B：Vercel 正式版本 | 约 30 人，≤300 流程/月 | ¥144–225/月 | Vercel Pro、低量托管 PostgreSQL 和轻量持久化队列的估算范围；实际数据库最低消费可能成为主要变量。 |
| C：腾讯云正式执行面 | 约 30 人，≤300 流程/月 | ¥100–610/月 | 以 API 网关、SCF、TDMQ、企业 PostgreSQL、COS 和 CLS 的低量级组合估算；函数调用用量很低，主要成本来自数据库、队列、日志、对象存储和高可用要求。 |

人数从 10 人增加到 30 人，流程量按相同方法从约 100 增至约 300 个/月；这不会让方案 B 或 C 的成本简单变为三倍，因为两种方案的主要成本是订阅和托管资源的最低消费，而不是函数调用次数。

上述金额不包含妙搭和飞书企业合同、AI Token、OCR、域名、备案、证书、WAF、安全合规、数据迁移和研发运维人力。对约 30 人的正式上线，基础设施用量通常不是成本主因；企业合规资源、托管数据库与运维要求更可能决定最终预算。

在采购或正式承诺前，必须基于真实的报销频率、审批节点数、附件容量、日志留存、AI 调用与企业合同重新验证成本。

## 8. 与 ADR 的关系

以下类型的决定必须新增 ADR，而不能只更新本文件：

- 改变飞书事件入口协议或同步/异步职责边界。
- 改变已发布配置、任务、审批或审计的权威数据源。
- 改变妙搭、业务后端和执行平台的核心职责分工。
- 从 Vercel POC 切换到正式国内云、企业容器或其他生产执行面。
- 引入会改变授权、安全边界或数据驻留方式的 AI/Agent 平台。

不改变架构边界的供应商参数、容量、价格、实施进度和验证结果可直接更新本文件。ADR 被接受后，应同步更新下一版 POC/生产架构基线与相关迁移计划。

## 9. 下一步

1. 完成报销 POC 的端到端验收和回调可靠性测试。
2. 向企业确认首选云、数据分级、数据驻留、网络、采购、数据库和模型供应商限制。
3. 以真实试点规模完成网关、数据库、队列和日志成本测算与压测。
4. 对会改变架构边界的结论创建 ADR，再进入生产迁移实施。
