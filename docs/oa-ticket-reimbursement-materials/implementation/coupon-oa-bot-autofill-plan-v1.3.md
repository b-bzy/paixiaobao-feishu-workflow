# 优惠券 OA 机器人端自动填报实施方案 v1.3

> 状态：实施中
> 定位：P1-1 的 Excel 内网试点范围以 [P1 PRD v1.5](../specifications/coupon-oa-p1-excel-pilot-prd-v1.5.md) 为准；本方案仅覆盖满足前置条件后的后续 OA 自动填写与确认即提交能力。
> 日期：2026-09-29
> 变更：v1.3 依据飞书官方 SDK 核实，创建/读取原生审批实例使用应用 tenant access token，并以 `open_id` 指定申请人；取消 OAuth 作为自动填单的前置依赖
> 变更：v1.2 将业务字段 schema 与飞书审批控件绑定合并为单一「提交 schema」；删除独立映射表，避免双配置漂移
> 变更：v1.1 新增「系统业务草稿」层——未确认数据暂存自有系统（Base），支持中断续填；与 ADR-0004 提交边界一致
> 决策依据：[ADR-0004 系统业务草稿与机器人确认即提交模式](../../adr/0004-bot-confirmed-submit-for-coupon-oa.md)
> 前置调研：草稿 API / URL 预填 / 身份要求均已实测验证（见 §2）

## 1. 目标

业务员在飞书机器人中完成优惠券 OA 的字段采集与材料校验，采集数据**暂存自有系统（系统业务草稿）**，可跨会话续填；经**人工预览确认**后，服务端使用应用 tenant access token、以业务员 `open_id` 作为申请人创建真实 OA 审批实例；单一提交 schema 保证"审批人看到的 = 业务员确认过的"，控件编码或绑定不一致时自动发现并止损。

## 2. 已验证的技术事实（2026-09-29 实测）

| # | 事实 | 证据 |
| --- | --- | --- |
| F1 | 飞书审批**无"创建草稿"开放 API**（客户端草稿为纯 UI 功能） | 全量 1752 个官方端点核查：审批模块 0 个 draft 端点；6 个猜测路径实测 404 |
| F2 | **无 URL 预填表单能力**，发起链接只能打开空白表单 | 官方文档检索；仅 create-instance 的 form 参数可预填 |
| F3 | 「创建审批实例」和「获取单个实例」支持应用 tenant access token；创建请求以 `open_id` 指定申请人。撤回实例仍需提交人用户身份或在客户端操作 | 飞书官方 Go SDK `approval/v4/instances`、`approval/v4/instances/:instance_id` 与 recall 资源定义 |
| F4 | 撤回仅限「审批中」状态；撤回后变「已撤回」，不可编辑重提 | 官方 API 描述 |
| F5 | 当前用户可发起列表（20 个定义）中**不含**「优惠券 OA 审批」 | `approvals search` 实测；需流程管理员提供 approval_code 并调整可见范围 |
| F6 | 租户内审批定义混合存在原生与三方（is_external）；本方案仅适用**原生**定义 | approvals search 结果 |

## 3. 用户交互流程：三道核对关

```text
业务员发口令「OA优惠券审批」→ 入口卡 [机器人帮我填]
        ↓
卡片表单采集（16 字段，提交 schema v1.0）+ 两表一图路径登记
  每步落【系统业务草稿】（Base，draftId + 状态机）：
  draft → validated → confirmed → submitted → canceled/failed
  中断可随时「继续填写」恢复；活动开始日已过的草稿标记过期
        ↓
【第 1 关 机器预检】校验报告卡（人只看异常项）
  必填/枚举/格式；时长=结束−开始+1；ROI=GMV÷费用
  OA 数值 vs 配券表「单渠道/全渠道」口径命中
  活动背景券档 ↔ 配券表 ↔ 白名单工作表一致性
  与上一期实例字段 diff（GMV/费用/券档环比标黄）
        ↓
【第 2 关 人工预览门】预览卡按 OA 页面同序全量展示，变化高亮
  [确认提交] / [返回修改]；可选冷静期（确认后延迟提交，期间可取消）
  确认动作落审计（谁/何时/确认的哪一版）
        ↓
【第 3 关 提交后撤回窗】
  服务端以 tenant access token、申请人 open_id 创建实例（即提交）
  1~2 秒内回读实例表单，与确认预览逐字段 diff
  一致 → 回发单据链接；不一致 → 立即告警 + 一键撤回引导（客户端撤回）
        ↓
业务员在飞书审批中补传附件、最终核对；审批人正常审批
```

**附件（W4）**：审批 API 附件控件需先经「上传文件」接口换取 file code；POC 首期先支持满减测算图片，配券表/白名单由业务员在单据页手工补传。

## 4. 架构与模块（Nitro，`server/lib/feishu/coupon-oa/`）

| 模块 | 职责 |
| --- | --- |
| `approval-schema.ts` | **唯一提交 schema**：16 个字段的业务 key/类型/必填/枚举/单位，与飞书控件 ID/类型/编码及解码规则同源维护；W1 从「查看审批定义」生成初始绑定并经人工确认；计算定义结构哈希，结构变化时 fail-closed |
| `validation.ts` | 机器预检全部规则（§3 第 1 关） |
| `preview-card.ts` | 采集卡、校验报告卡、预览确认卡、结果卡 |
| `approval-client.ts` | 以 tenant access token 读取定义、上传审批附件、创建/回读审批实例；创建请求只带申请人 open_id、form 与幂等 uuid，绝不覆盖节点审批人或抄送人 |
| `draft-store.ts` | 系统业务草稿：Base 生命周期表（与审计表合并），草稿 CRUD、状态机、续填恢复、过期标记；skill 的 `fields.json` 可导入同一事实源 |
| `audit-store.ts` | 提交审计：确认快照、提交 schema 版本、审批定义结构哈希、实例 code、回读 diff 结果、操作者/时间 |

**止损链**（回读不一致或业务员反悔）：客户端一键撤回（提交人本人）→ 引导卡直达单据页；服务端不冒用用户身份撤回；仍不可用时请第一审批人驳回。

## 5. 分期与里程碑

| 期 | 内容 | 出口标准 |
| --- | --- | --- |
| **W0 前置确认** | 流程管理员：提供 approval_code、定义对业务员/应用开放、确认撤回规则允许提交人撤回；应用管理员：审批定义读取、实例创建/读取、附件上传与 Base 读写权限审批 | 清单逐项落名 |
| **W1 提交 schema Spike** | 用 tenant access token 读取目标定义，生成初始提交 schema（字段语义 + 控件绑定 + 编码/解码规则）并做 form 组装→创建→回读→比对的端到端演练 | 演练单回读 diff = 0；单一提交 schema 经业务确认 |
| **W2 采集与校验** | 提交 schema、系统业务草稿存储与续填、采集卡、机器预检、预览确认卡、上期 diff | 草稿中断续填与过期标记可用；校验规则单测全绿；案例 202609240455 数据复跑通过 |
| **W3 提交网关** | tenant token 审批客户端、创建+回读比对+止损链、提交 schema 定义哈希守卫、审计落 Base | 确认前零副作用；回读不一致演练必须触发失败告警 |
| **W4 附件** | 测算图片上传→file code→控件赋值 | 图片进入实例附件，哈希留档 |
| **W5 端到端验收** | 真实定义灰度：试点业务员全流程 ≥3 单 | 见 §7 |

## 6. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 控件绑定或编码错误 | 单一提交 schema 消除双配置；审批定义结构哈希变更时 fail-closed；创建后使用同一 schema 回读 diff 并自动告警止损；演练定义 round-trip 回归 |
| 业务员误确认 | 机器预检 + 全量预览 + 可选冷静期；撤回窗口横跨人工审批节点（券配置在部门审批之后） |
| tenant token 泄露 | App Secret 只保存在 Vercel 服务端环境变量；最小审批与 Base scope；不向浏览器、卡片或日志输出 token |
| 目标定义是三方审批 | W0 核实 is_external；若是三方，本方案不适用，另立方案（单据实际在外部系统） |
| 撤回被管理员禁用 | W0 确认；若禁用则止损只剩"第一审批人驳回"，需业务 Owner 书面接受 |
| 草稿与实例状态脱节 | 数据单向流（草稿→实例，实例表单不可改）；订阅审批事件回写 submitted/canceled 状态，不一致时告警 |
| 过期草稿误提交 | 提单前强制复验活动日期；开始日已过的草稿只读并提示新建 |

## 7. 验收标准

1. 确认卡不点击，飞书侧无任何单据产生（含演练定义以外的零写入）。
2. 审批人看到的实例表单与业务员确认的预览逐字段一致；人为注入控件绑定或编码错误的演练必须被回读比对拦截并完成撤回。
3. 审批定义控件变更后，未更新提交 schema 前提下的提单被拒绝并告警。
4. 每单审计记录完整：确认人/时间/提交 schema 版本/审批定义结构哈希/实例 code/回读结果。
5. 采集中断后凭 draftId 恢复续填，字段与中断前一致；过期草稿无法直接提交。
6. 试点业务员从发口令到提交 ≤ 5 分钟；撤回演练 ≤ 1 分钟完成。
