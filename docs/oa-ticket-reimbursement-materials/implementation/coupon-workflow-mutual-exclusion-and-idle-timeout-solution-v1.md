# 优惠券双草稿冲突与懒过期治理方案 v1

> **状态**：已实现（代码）；生产 Base 数据与部署尚未修改
> **日期**：2026-09-30
> **范围**：机器人 `OA优惠券填报` 系统草稿与 `优惠券Excel试点` 系统草稿
> **关联**：[测试用例 v1](coupon-workflow-mutual-exclusion-and-idle-timeout-test-cases-v1.md)

## 1. 问题与根因

截图中的“无法判断文件用途”不是文件名、扩展名或 Excel 内容错误。它表示同一个 `open_id` 同时有一条活跃的优惠券 OA 草稿和一条活跃的 Excel 试点草稿；系统为避免把文件挂到错误流程而停止处理。

根因是入口互斥校验不对称：

1. `优惠券Excel试点` 会检查活跃的 OA 草稿；
2. `OA优惠券填报` 原先不会检查活跃的 Excel 试点；
3. OA 表单保存时也没有再次检查 Excel 试点；
4. 因而用户可以先启动 Excel、再保存 OA 草稿，直到上传文件才被拦截。

相关原始路径：

- 附件冲突拦截：`server/lib/feishu/events.ts`
- OA 草稿保存：`server/lib/feishu/events.ts`
- Excel 试点入口：`server/lib/feishu/events.ts`
- 冲突卡片：`server/lib/feishu/coupon-oa/excel-pilot-cards.ts`

## 2. 已采用的策略

本期不引入 Cron、队列、Worker 或外部调度器。用户选择的超时语义为：

```text
最后一次成功持久化的有效业务操作
  ↓ 超过 10 分钟
下一次与该优惠券流程相关的文本、文件或卡片回调到达
  ↓
系统先将旧草稿置为 Canceled，再拒绝旧操作或继续新的发起动作
```

因此：

- 系统**不会**在用户完全无操作时，于第 8 分钟主动提醒；
- 系统**不会**保证在第 10 分钟精确主动发出终止卡；
- 用户下一次继续操作时，过期流程一定不会重新接管文件或被旧卡片复活；
- 用户可重新发送对应指令开启新流程。

这是现有 Nitro + Vercel + 飞书 Base POC 在不增加调度基础设施下的可靠边界。

## 3. 修复内容

### 3.1 单活跃流程保护

对同一 `open_id`，正常 Bot 操作只能保留一个可继续的流程：

| 操作 | 已有 OA 草稿 | 已有 Excel 试点 |
| --- | --- | --- |
| 发送 `优惠券Excel试点` | 不创建 Excel；展示 OA 流程结束入口 | 继续已有 Excel |
| 发送 `OA优惠券填报` | 打开/继续 OA 表单 | 不打开 OA 表单；展示 Excel 流程结束入口 |
| 保存 OA 表单 | 更新 OA 草稿 | 再次拦截，不创建 OA 草稿 |
| 发送附件 | 路由到 OA 附件处理 | 路由到 Excel 白名单处理 |

OA 表单打开前和保存前均检查 Excel 试点。第二次检查用于覆盖用户打开旧表单后再从其他设备启动 Excel 流程的常见情况。

### 3.2 冲突恢复与手动结束

新增以下卡片操作：

- `coupon_oa_cancel`：草稿创建人结束可取消的 OA 草稿；
- `coupon_excel_pilot_cancel`：试点创建人结束可取消的 Excel 试点；
- 历史双活跃状态展示两个结束按钮，用户明确选择结束其中一个；
- 结束后的重复点击只返回“已结束”，不重复写入。

取消仅改变系统草稿为 `Canceled`。它不撤回、修改或提交飞书原生 OA；已提交、需人工复核或已确认生成的终态记录也不能被本功能取消。

### 3.3 10 分钟懒过期

新增 `workflow-lifecycle.ts`，以 Base 返回的时间戳判定最后一次成功持久化的有效操作：

1. 优先使用 `updatedAt`；
2. 记录尚未修改时回退 `createdAt`；
3. 满 10 分钟后，仅对可取消状态执行 `Canceled`；
4. `Confirmed`、`Submitting`、`Submitted`、`CreatedNeedsReview`、`GeneratedConfirmed` 等不因本机制自动结束；
5. 重复事件、无效输入、纯展示卡片和旧回调不会延长或重新激活流程。

过期处理发生在附件路由、流程入口、Excel 映射确认、Excel 确认回调、OA 确认/提交回调与 OA 表单保存之前。文件下载、审批附件上传、Excel 生成和正式 OA 提交前均不会使用已过期草稿。

## 4. 交互文案

### 已有另一条流程

> **已有未完成的优惠券流程**
>
> 为避免文件归属错误，不能同时启动另一条优惠券流程。请继续当前流程，或点击“结束当前流程”后重新发起。

### 历史双草稿冲突

> **存在两个未完成的优惠券流程**
>
> 为避免文件误挂到错误申请单，系统未处理本次文件。请选择结束 OA 草稿或结束 Excel 试点后再继续。

### 懒过期

> **优惠券流程已结束**
>
> 该草稿超过 10 分钟未继续操作，已在本次操作到达时结束。未创建或提交正式 OA；如需继续，请重新发送对应指令。

## 5. POC 边界与后续建议

1. 当前飞书 Base 的跨表读取和更新不是数据库级原子互斥。入口双检可阻止正常单聊流程再次产生冲突，但两次完全并发的 Serverless 请求不能获得事务级唯一保证。
2. 当前实现只覆盖服务端已保存的 `OA优惠券填报` 与 `优惠券Excel试点` 草稿。仅打开原生 OA URL 的 `OA优惠券审批` 不创建系统草稿，不参与本机制。
3. 若后续需要“用户完全无操作时精确 8 分钟提醒、10 分钟自动终止”，必须新增持久化 `lastActivityAt` / `expiresAt` 与受保护的周期任务或延迟队列；不能使用 Serverless 进程内 `setTimeout`。
4. 若试点扩大至高并发或多人协作，应引入带唯一约束和条件更新的持久化会话/租约存储，再实现严格的每用户单活跃流程保证。
