# 优惠券 OA 智能提单 MVP PRD v1.2

> **状态**：当前有效产品基线  
> **版本**：v1.2  
> **日期**：2026-09-28  
> **变更**：替代历史“POP 优惠券邮件草稿助手”方向。P0 改为直接引导业务员打开既有飞书优惠券 OA 审批表；P1/P2 再逐步建设自动填单与附件能力。

## 1. 背景与目标

优惠券提报当前依赖业务员在飞书 OA 中自行找到正确审批表、填写信息并准备附件。首期的目标不是重造审批流，而是降低“找表单”的入口成本：业务员只需在飞书机器人中输入固定口令，即可获得对应的原生 OA 发起入口。

本 PRD 采用渐进式建设：先验证正确表单入口和权限，再实现受控的数据写入与附件上传，最后实现配券 Excel 的自动生成与上传。任何阶段均不得自动审批、绕过 OA 权限或在未经业务员确认的情况下提交审批。

## 2. 用户、前提与原则

| 项目 | 说明 |
| --- | --- |
| 目标用户 | 已获授权发起优惠券 OA 的业务员 |
| P0 前提 | 流程管理员提供稳定的优惠券 OA **发起链接**，并已在飞书 OA 中为目标业务员配置表单权限 |
| 机器人职责 | 识别口令、返回入口卡片、明确能力边界 |
| 飞书 OA 职责 | 对打开链接的业务员做原生身份与表单权限校验，承载填写、提交、审批和流转 |
| 配置方式 | 服务端环境变量 `FEISHU_COUPON_OA_INITIATE_URL`；不得提交真实链接、密钥或个人凭据 |

**核心原则**

1. P0 只导航到既有 OA 表，不创建、代填、代提交或代审批。
2. 机器人不能授予或绕过 OA 权限；无权限用户由飞书 OA 拒绝，并联系流程管理员处理。
3. P1/P2 的字段、附件、模板和映射均须版本化、可审计，并经业务与流程 Owner 确认。
4. 自动化只减少重复录入；审批判断、最终核对与提交始终由业务员和现有审批流承担。

## 3. 分期范围

| 阶段 | 目标 | 用户输入 | 系统输出 | 明确不做 |
| --- | --- | --- | --- | --- |
| **P0** | 获取正确 OA 表单 | `OA优惠券审批` 口令 | 打开既有优惠券 OA 审批表的卡片 | 写入/提交 OA、附件、Excel、规则校验、审批自动化 |
| **P1** | 自动填写 OA 并上传已有材料 | 受控结构化字段 + 业务员已提供的附件 | 待业务员复核的 OA 表单内容和附件 | 生成 Excel、自动提交、自动审批 |
| **P2** | 自动生成配券表并作为附件上传 | P1 字段 + 已确认的业务规则 | 由受控 Excel 模板生成的配券信息表，挂载至 OA 附件 | 模型自行推断规则、自动提交、自动审批 |

## 4. P0 功能需求

### 4.1 发起与交互

1. 业务员向机器人发送 `OA优惠券审批`；口令中的空格可忽略，其他文本不触发。
2. 机器人回复“优惠券 OA 审批表”卡片，其中包含“打开优惠券 OA 审批表”按钮。
3. 点击按钮后，飞书打开流程管理员配置的原生 OA 发起链接。
4. 业务员在原生 OA 中自行填写、核对和提交；机器人不接收表单字段，也不显示“已提交”或“已审批”。
5. 飞书消息事件重复投递时，机器人按事件 ID/消息 ID 幂等发送入口卡，避免重复消息。

### 4.2 权限与配置

- 服务端仅读取 HTTPS 的 `FEISHU_COUPON_OA_INITIATE_URL`；URL 缺失、格式错误或非 HTTPS 时不得生成跳转按钮。
- P0 需要的机器人权限仅限于接收消息事件和发送交互卡片。OA 表的使用权限由既有飞书 OA 配置控制，不由机器人或服务端授予。
- 没有 OA 表单权限的用户在打开后应由飞书原生页面拒绝或提示；机器人提示其联系流程管理员，不尝试冒用他人身份。
- P0 不保存 OA 表单字段、附件、OA 单号或审批状态，也不调用审批实例创建 API。

### 4.3 异常处理

| 场景 | 系统行为 | 用户可见结果 |
| --- | --- | --- |
| 未命中精确口令 | 不触发优惠券 OA 流程 | 无优惠券 OA 卡片 |
| 入口 URL 未配置/非法 | 返回无跳转的错误卡，不暴露配置值 | 联系流程管理员配置表单入口 |
| 业务员无 OA 权限 | 保持由飞书 OA 原生校验 | 联系流程管理员开通表单权限 |
| 飞书消息发送失败 | 接口返回失败，依赖飞书事件重投和消息幂等 | 不将失败伪装成已发送 |
| 打开表单后填写/提交失败 | 不由 P0 处理 | 使用飞书 OA 原生错误提示/支持渠道 |

## 5. P1：自动填写 OA 与上传已有附件

P1 在确认飞书 OA 的获授权写入能力、目标表单的稳定字段标识和附件 API 后实施：

- 维护版本化字段 schema、表单字段映射、必填规则与允许的附件类型/大小；
- 采集业务员确认的结构化数据，写入对应 OA 草稿/待提交表单；
- 上传业务员提供且通过安全校验的附件，并将附件关联到同一申请修订；
- 在提交前展示完整预览和校验结果，必须由业务员确认；
- 记录字段版本、附件哈希、操作者、时间与 OA 引用，支持审计与重试。

P1 不生成 Excel、不自动点击提交、不处理审批结论，也不允许模型自行补全业务事实。

## 6. P2：自动填写 Excel 并作为附件上传

P2 在 P1 基础上接入已确认的标准配券 Excel 模板：

- 每份模板维护版本、工作表、单元格/列映射、公式与输出文件名；
- 由同一申请修订中的受控字段填充模板，生成可预览的 `.xlsx`；
- 对必填项、枚举、金额、日期、行数、公式和模板版本执行受控校验；
- 业务员确认预览后，将生成文件作为对应 OA 的附件上传；
- 保存生成文件哈希、模板版本和 OA 附件引用，确保可追溯。

P2 不允许从自由文本推断券规则、覆盖原始模板公式、自动提交 OA 或自动审批。

## 7. P0 验收标准

1. 配置有效 HTTPS 发起链接后，业务员发送 `OA优惠券审批` 可收到带正确链接的原生 OA 入口卡。
2. `O A 优 惠 券 审 批` 等仅含空格差异的口令同样生效；“我的 OA优惠券审批到哪了”等非精确文本不误触发。
3. 事件 ID 或消息 ID 重复投递时，发送卡片使用相同幂等键。
4. 未配置、无效或非 HTTPS URL 时，业务员只能看到配置提示卡，无法获得跳转按钮或敏感配置内容。
5. 使用有/无 OA 权限的测试账号打开链接，分别验证正常使用和飞书原生拒绝；P0 不产生权限绕过。
6. 全流程不调用 OA 创建、表单写入、附件上传、邮件草稿、自动提交或审批 API；现有报销机器人流程不受影响。

## 8. 非目标与后续门槛

P0 不建设管理后台、规则中心、审批状态同步、附件存储、Excel 生成或批量提单。进入 P1 前必须由流程管理员确认 OA API/表单字段的获授权访问方式；进入 P2 前必须由业务 Owner 确认真实 Excel 模板、字段定义和校验口径。
