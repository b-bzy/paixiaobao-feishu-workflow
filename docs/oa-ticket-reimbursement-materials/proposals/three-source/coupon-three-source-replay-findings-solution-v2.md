## 1. 恢复卡组件同名 → 飞书 11310 整卡拒收 → 静默死局【高】

**决定**：按方案 B 修复，不动摇。

| 修复 | 内容 | 落点 |
| --- | --- | --- |
| 去重 | 可选补充区排除已进待修正区的字段，一个字段只画一次 | 整合计划 Task B2 |
| 必达 | 恢复卡发送失败降级纯文字报错 + 结构化日志，不再静默 | Task B4 |

## 2. 一份材料混多维度（商家 ID + SKU）→ 按维度各自成表【高，归 scalable】

**Owner 决定**：商家 ID 一张表、SKU 一张表，不混装。

**方案（v2 细化到列级）**：
- 拆分粒度 = **列**：同一 Sheet 内按列头/识别维度分组（case9 实测形态：`sku id` 列与 `商家id` 列并存、SKU+SPU 同 Sheet）——SKU 维度列进 SKU 冻结产物，商家 ID 列进商家 ID 冻结产物；
- 同维度多 Sheet 合并为该维度产物的多券档（维持现状语义）；
- 每个维度产物独立模板 id/hash/表头（SKU=`sku`，商家ID=`商家id`，复用方案 A 的产物维度化设计）；
- 配券表「限品类型」按名单实际维度写入（限SKU/限商家ID，方案 A 已设计）；
- **依赖**：单维度（整表唯一维度）场景方案 A 落地即覆盖；**跨维度多名单并行**（一次提报同时存在 SKU 券与商家 ID 券两组名单）需管线从"单白名单槽位"扩展为"按维度分组的多名单"，归 scalable recognition 立项，与多配券表、内嵌名单列、多文件角色队列（BUG-9-1）同批设计。

## 4. 枚举字段：选择组件化 + 默认值预填【中，Owner 新裁定】

**Owner 决定**：按系统标准来（不做方言归一）；**由系统提示的字段一律改成选择项，并把默认值写上去，少犯输入错误**。

**字段清单与改法**（封闭枚举全集来自 `calculation.ts` schema）：

| 字段 | 合法值 | 现状 | 改法 | 默认值 |
| --- | --- | --- | --- | --- |
| 领取规则 claimRule | 活动期间仅可领一次 / 活动期间每天可领一次 | 恢复卡自由文本框 | `select_static` | **活动期间每天可领一次**（Owner 指定） |
| 是否允许转赠 allowGift | 允许 / 不允许 | 恢复卡自由文本框 | `select_static` | 不允许（建议，待 Owner 确认） |
| 推广途径 promotionMode | 公开自动推广 / 非公开推广 | 卡上无独立入口（取表值） | 值缺失/非法时的修正入口用 `select_static` | 无默认（业务关键分支，不预选） |
| 公开推广渠道 publicPromotionChannels | 全网推广/单品页购物车/领券中心/公开券池（可多选） | 自由文本框 | **checkbox 群组**（select_static 不支持多选） | 无默认（公开途径时必填≥1，方案 B 改动1 已覆盖必填渲染） |
| 业务模式 businessMode | 严选/寄卖/pop | ✅ 已是 select | 维持 | 表值优先 |
| 是否超扣 overDeduction | 是/否 | ✅ 已是 select | 维持 | 表值优先，无表值预选"否" |

**默认值规则**（写进实现约束）：表内值合法 → 预填表内值；表内值缺失或非法 → 预填上表默认；默认值仅为**可改的预选**，owner 提交为准，不改写任何表内原值（与"不做方言归一"一致——默认值只影响表单初值，不碰事实）。

**落点**：与整合计划 Task B2 同区域（cards.ts 渲染），随阶段一实现；dispatcher 解析同步（checkbox 多值合并为数组）。**验收**：老格式 case（1/8）映射卡上枚举字段全部点选完成、零手打；表值非法时默认值预选可见。

## 6. 🆕 测算图两个缺陷：中文豆腐块 + 一次 5 张【高，修复已在工作区待落库】

### 现象与根因（已核实到代码）

- **部署在跑的是老渲染器**（HEAD=b466413）：`rowsPerPage=24; columnsPerPage=8` 硬拆页——case3 冻结表 27 列 → 列块×行块组合出 **5 张**，每页重复渲染表头行且列宽被压缩；
- **中文豆腐块**：老渲染器 SVG `font-family` 回退链最终落到 Arial（无中文字形）；本机 macOS 自动回退苹方所以"看起来正常"，**Vercel Preview 的 Linux 环境无任何中文字体** → 数字正常、中文全变 □。部署产物与本地所见不一致，这正是重放测试里 Preview 链路的图。

### 修复（另一工作线已实现，未提交；本次已 review + 测试验证）

| 项 | 实现 | review 结论 |
| --- | --- | --- |
| 分页 | 像素预算制（单页 ≤12M 像素）**只按行分页，全列单页**；27 列单页实证（样图 1of1） | ✅ 测试 3/3 绿（含"全列单页、超预算才分行"用例） |
| 字体 | Noto Sans SC 变量字体（17.8MB，含 OFL 许可证）经 Nitro assets 打包 → 运行时写 `/tmp` + `FONTCONFIG_FILE` 指向独立配置 → **本地与 Vercel 只见同一内置字体，渲染强制一致** | ✅ 方向正确且优于"修 Vercel 环境字体"（一致性根治） |
| 版本 | `couponCalcImageRendererVersion` 升 `coupon-calc-image-v2`，产物可辨识 | ✅ |

### 剩余闭环（本方案要做的）

1. **落库与部署**：修复目前是未提交改动（含 `calc-image.ts`/`calc-image-font.ts`/`calc-image.test.ts`/`nitro.config.ts`/配套文档），Preview 仍在跑老逻辑——需由其 owner 提交 → 重部署 → 生效；
2. **部署体积验收**：17.8MB 字体进 serverless 包，部署后确认构建产物体积与首次渲染延迟可接受；
3. **真发验收**：部署后任跑一个 case，Preview 生成的测算图应**单张、中文正常**——本地测试证明不了 Vercel 侧行为，必须看真图（fontconfig 隔离的价值在一致性，但也需一次实拍确认）；
4. **加固建议**：`ensureBundledCjkFont` 加载失败目前静默返回 false（Linux 会回豆腐但不中断流程）——建议补一条一次性结构化日志，便于部署侧发现字体未打包类问题；
5. **约束**：`FONTCONFIG_FILE` 仅在 fontconfig 首次初始化生效，当前全库仅测算图一处 SVG 文本渲染，安全；后续任何新增 SVG 文本渲染必须复用同一字体初始化（写入实施基线提醒）。

## 10. 2026-10-18 修订：软门禁取代硬拒绝（Owner 实际使用反馈后裁定）

- **背景**：Owner 以真实业务（乐器 case）实际使用时被「领取规则=每天可领一次」退回，反馈"宁可通过也不要每次退回"，推翻 §4 中 10-16「不做方言归一」的裁定。
- **实现（8fa5eb2）**：`calculation.ts` 增加封闭枚举的**宽容归一**——表值/填写值能无歧义映射到唯一标准值时（每天可领(1)次→活动期间每天可领一次、是→允许、非公开→非公开推广、POP→pop 等），校验前自动采用标准值继续流程；映射不动的仍严格拒绝（保留溯源中文报错）。映射卡片新增「已按标准值处理」披露区，确认快照保留标准值供审计；源单元格不改写。
- **真发验证**：卡死的乐器草稿（rev4）重新确认即通过至 DraftOnlyConfirmed，claimRule 落为标准值，产物与 OA 草稿齐备。
- **已知边界**：映射表按前缀/关键词设计，新方言需增补规则（集中在 `enumCanonicalRules` 一处）；语义真歧义的值不会被误映射。
