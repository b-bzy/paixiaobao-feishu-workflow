# 优惠券 Excel 试点 Drive 下载 403 诊断与恢复

> **当前依据**：阶段与 go/no-go 以 [rollout](../../current/operations/coupon-oa-internal-pilot-rollout-plan-v1.md) 为准。

> **日期**：2026-09-30
> **范围**：Bot「优惠券Excel试点」在确认已生成 Excel 后，将冻结的 Drive 文件提升为系统 OA 草稿的审批附件。
> **结论状态**：已确认生成与 Base 附件写入成功；Drive 下载接口返回 HTTP 403，等待应用 Drive 下载权限发布后复测。

## 1. 真实联调现象

本次试点已成功完成：

```text
字段确认
→ 白名单上传与映射
→ 生成两份 Excel
→ 普通 Drive 冻结文件写入成功
→ Base 两个附件字段写入成功
```

在点击当前 `确认生成结果` 后，Bot 显示：

```text
自动填写 OA 未完成
两份 Excel 已冻结，但尚未创建系统 OA 草稿。
原因：Feishu Drive file download failed: 403
```

失败发生在系统 OA 草稿创建之前；没有创建或提交原生正式 OA。

## 2. 保留的文件与安全边界

每份生成文件仍有两个不同用途的标识：

| 标识 | 所在位置 | 用途 |
| --- | --- | --- |
| `fileToken` | 配置的普通 Drive 文件夹 | 冻结版本、下载后 SHA-256 校验、上传审批附件库 |
| `baseFileToken` | Excel 试点 Base 的 `bitable_file` 媒体 | 仅用于 Base 附件字段可见性 |

本问题不能以 `baseFileToken` 替代 `fileToken`，也不能跳过下载后的字节数和 SHA-256 校验。这样做会破坏“确认的是哪一份 Excel，提升到 OA 的就是哪一份”的完整性边界。

## 3. 当前判断

系统调用的是飞书 Drive 媒体下载接口：

```text
GET /drive/v1/medias/{file_token}/download
```

该接口路径与生成文件返回的普通 Drive `fileToken` 相匹配。HTTP 403 表明应用身份还不能读取/下载该 Drive 文件，常见原因是：

1. 自建应用缺少 Drive 的读取/下载权限（通常在开放平台显示为 `drive:drive:readonly`，或租户当前对应的 Drive 读取下载权限）；
2. 权限虽已配置但应用新版本尚未发布或尚未获管理员批准；
3. 应用不再拥有配置 Drive 文件夹的协作者权限。

代码已保留下载接口的飞书错误 `code` / `msg`（如果响应为标准 JSON），以便下次失败时区分具体权限原因；不会输出令牌、文件内容或密钥。

## 4. 恢复步骤

1. 在飞书开放平台的自建应用权限管理中，添加或确认 **Drive 文件读取/下载** 权限；不要仅保留上传权限。
2. 创建并发布包含该权限的应用版本；如组织要求审批，等待管理员批准。
3. 确认应用仍是配置 Drive 文件夹的编辑者。
4. 无需重新生成、重新映射或重新上传白名单。保留当前两份冻结 Excel。
5. 无需重启桥接或重新上传。下一次重试会重新获取 tenant access token；确认应用版本已发布后再操作。
6. 仅点击当前失败卡的 `重试自动填写 OA 草稿` 一次。

重试只会继续当前试点版本：

```text
下载冻结的 Drive 文件
→ 校验大小与 SHA-256
→ 上传审批附件库
→ 创建系统 OA 草稿
```

它不会自动创建原生正式 OA，也不会触发最终 `确认提交正式 OA`。

## 5. 复测验收

完成权限发布后，预期流程是：

```text
重试自动填写 OA 草稿
→ 两份冻结 Excel 下载并通过 hash 校验
→ 系统 OA 草稿已自动填写
→ 寄卖 / pop：提示手动上传满减测算图片
→ 人工预览
```

到达人工预览后，本轮测试停止在最终 `确认提交正式 OA` 按钮之前。
