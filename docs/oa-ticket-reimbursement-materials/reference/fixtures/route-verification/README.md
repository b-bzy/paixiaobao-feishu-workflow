# 优惠券 OA 自动提交路径验证：脱敏测试样本

> **用途**：仅用于“系统 API 提交”和“人工原生 OA 提交”的双单路径对照。文件中不含真实商品、客户、经营金额或可用优惠券配置。  
> **严禁**：上传到正式审批定义、建券系统或生产环境；只能用于流程管理员准备的演练审批定义。

## 固定测试字段

| 正式 OA 字段 | 值 |
| --- | --- |
| 申请类型 | 优惠券申请 |
| 业务模式 | 寄卖 |
| 活动名称 | `【自动填报演练，请勿配置】寄卖满减券` |
| 活动背景 | 本申请仅用于验证自动填报与原生提交的审批路径一致性，不产生、不配置、不启用真实优惠券或商品。 |
| 是否超扣点 | 否 |
| 预估 GMV | ¥10,000 |
| 预估费用 | ¥100 |
| 预期 ROI | 100（正式 OA 公式控件计算，不作为 API 输入） |
| 配置渠道 | 京东渠道；严选 APP 及小程序 |
| 活动周期 | 2030-01-01 至 2030-01-01，共 1 天 |

部门和申请人必须由**同一位测试业务员**在 A/B 两单中以其真实飞书身份填写/授权，不在测试样本中伪造。

## 附件

- `满减测算图片-自动填报演练.png`：测试图片；
- `配券信息表-自动填报演练.xlsx`：两条测试渠道配置，所有 ID、链接和名称均为不可用的演练值；
- `商品明细白名单-自动填报演练.xlsx`：仅含虚构 `TEST-SKU-*` 标识；
- `test-submission.json`：机器可读的字段快照和附件 SHA-256，供 A/B 提交前复核和提交后比对。

## 执行顺序

1. 流程管理员确认演练审批定义没有连接真实建券、启用同步、营销同步或经分生产动作。
2. 将 `test-submission.json` 的字段和三份附件用于 A 单（手工提交）；记录 A 的 `instance_code`。
3. 人工复核 B 单字段与附件哈希和 A 完全相同。
4. 在业务方再次确认后，才创建 B 单（API 模拟系统提交）。
5. 在 `route-comparison-report.md` 中记录两单对照结果；发现任何差异立即停止后续节点流转。
