## 1. 核心结论

1. **配券信息表不是单一模板**：系统必须根据券活动类型、用户范围和优惠方式自动选择对应模板，不能只提供一个通用 Excel 上传入口。
2. **一行代表一个活动批次**：同一活动若需在“京东商城”和“拍拍二手”两个渠道投放，须拆成两行，形成两个批次；每行的 `putKey` 与领券链接均不同。
3. **分层叠加规则**：不同层级的券可以叠加，同一层级的券不可叠加。限品类券（平台券）属于第五层；大促神券属于第六层。
4. **模板内存在自动回填字段**：活动 ID、批次 ID、配置 KEY、PC/M 端领券链接等由配券人员在券生效后反馈，不应要求业务员在 OA 发起阶段填写。
5. **模板内存在公式字段**：优惠券/折扣名称、优惠比例、预计费用和预估 ROI 等应由系统复用受控公式或等价服务端计算，避免让业务员手填或覆盖公式。

## 3. 标准模板的字段分组

### 3.1 配券结果回填字段（OA 申请时只读/留空）

下列列在常规、PLUS 和大促神券模板中出现，模板说明标注为“配券人填写，优惠券生效后反馈”：

- 活动 ID；
- 批次 ID；
- 优惠券活动配置 KEY（`putKey`）；
- PC 端领券链接；
- M 端领券链接。

**产品要求**：提报助手生成 Excel 时保留这些列和格式，但不得伪造值；回传复核阶段应将实际返回值写回，并与 OA 实例关联。

### 3.2 业务员填写字段

| 字段 | 适用范围/说明 |
| --- | --- |
| 特殊业务标签 | 仅大促神券模板；模板预置为“大促神券”。 |
| 领券用户 | PLUS 模板预置为“PLUS会员”；常规模板通常无此列。 |
| 用券渠道 | 业务填写。可选京东商城或拍拍二手；**单行只能填一个渠道**，两个渠道须拆为两个批次行。 |
| 申请人 | 填写优惠券申请人姓名。 |
| 可领时间 | 用户可领取/发放优惠券的时间。 |
| 可用时间 | 用户领券到账后可以使用的时间。 |
| 活动名称 | 按业务活动填写。 |
| 总申请数量 | 本次活动可发放张数的总上限。 |
| 单次发放到账张数 | 用户一次领取或一次发放时同时到账的券数量。 |
| 每日领取次数 | 每日支持领取的最大次数；例如单次到账 2 张、每日领取 500 次，对应最多 1,000 张。兑换券改用“个人最大兑换次数”。 |
| 面额、限额 | 满减券的减免金额与使用门槛。 |
| 折扣力度、折扣限额、最高减额 | 折扣券专用。折扣力度必须为正数且最多 1 位小数；折扣限额、最高减额必须为正数且最多 2 位小数。最高减额可导致折扣券存在两种模板示例情形。 |
| 预计领用率、预计使用率 | 按业务情况预估；模板提示可参考建券侧的历史批次数据。 |
| 拍拍平台承担比例 | 平台承担优惠券费用的比例；兑换券模板说明：严选和自营店铺默认平台承担 100%。 |
| 预计引入 GMV | 业务填写，用于计算预估 ROI。 |
| 优惠券类型、限品类型、领券用户风控、用户领券规则、优惠券赠送、推广途径、公开推广渠道 | 常规 / PLUS / 大促神券模板的配置项；兑换券模板中仅保留其中部分字段。具体选项与约束尚未在截图中给出，需补充官方枚举。 |
| 兑换类型 | 兑换券专用，填写“兑换码”或“兑换链接”。 |
| 个人最大兑换次数 | 兑换券专用，表示活动期间单用户最多兑换次数。 |

### 3.3 商品明细白名单 / 黑名单配置规则

商品范围附件的可配置维度仅为**商家 ID、SKU、SPU**三类，且每一份名单均须为单列数据、列内值准确、每个单元格只包含一个 ID。

| 配置维度 | 文件格式要求 | 业务组合限制 |
| --- | --- | --- |
| 商家 ID | 商家 ID 须位于单独一列且准确无误。 | 以商家 ID 建券时，可同时上传 SKU **或** SPU 黑名单，以剔除部分商品；SKU 和 SPU 黑名单只能二选一，不能同时操作。 |
| SKU | SKU 须位于单独一列且准确无误；每个单元格仅一个 SKU。 | 以 SKU 建券时，不可再对 SPU 操作。 |
| SPU | SPU 须位于单独一列且准确无误；每个单元格仅一个 SPU。 | 以 SPU 建券时，不可再对 SKU 操作。 |

**产品校验要求**：系统需解析白/黑名单附件的真实列数、列名和单元格值，拒绝多列、混填 SKU/SPU、空值、非法 ID 及未满足上述组合限制的文件；应识别并报告重复 ID，但是否对同一档位内或跨券档的重复值自动去重、阻断或保留，须由业务确认。商家 ID 建券叠加 SKU/SPU 黑名单的具体文件归属（白名单还是黑名单）、允许的 ID 数量上限和商品主数据校验接口仍需业务确认。

### 3.4 受控计算字段

| 字段 | 满减券模板现状 | 折扣券模板现状 | 产品处理要求 |
| --- | --- | --- | --- |
| 优惠券名称 / 折扣名称 | 满减名称按 `满{限额}减{面额}` 生成 | 折扣名称按 `最高减额{最高减额}内折扣` 生成 | 由系统自动生成；业务员不可手改。 |
| 优惠比例 | `面额 ÷ 限额` | 示例中填充或按业务规则计算 | 系统展示结果及计算依据；折扣券的最终口径待业务确认。 |
| 预计费用 | 标准模板使用“总申请数量 × 面额 × 预计使用率 × 平台承担比例”公式 | 标准模板使用“最高减额 × 预计领用率 × 预计使用率 × 平台承担比例 × 总申请数量”公式 | 首期必须以模板版本中真实公式为准；对输入为空、0 值、百分比格式和精度做校验。 |
| 预估 ROI | `预计引入 GMV ÷ 预计费用` | `预计引入 GMV ÷ 预计费用` | 自动计算；预计费用为 0 时阻断并提示，不能输出无穷大或空白结论。 |

> 以上预计费用公式根据当前 Excel 内置公式整理。兑换满减券沿用“总申请数量 × 面额 × 预计使用率 × 平台承担比例”；兑换折扣券沿用“最高减额 × 预计领用率 × 预计使用率 × 平台承担比例 × 总申请数量”。是否将“预计领用率”纳入满减券预计费用，须由业务确认后统一口径。

## 4. 配置字段说明一览表（截图转写）

| 编号 | 字段 | 定义 / 规则 |
| ---: | --- | --- |
| 1 | 可领时间 | 优惠券活动支持用户领取或发放的时间。 |
| 2 | 可用时间 | 用户领取到账后可使用优惠券的时间。支持绝对有效期（天/小时）和相对有效期（天/小时）。绝对按日默认起始 `00:00:00`、结束 `23:59:59`；按小时默认起始第 0 秒、结束第 59 秒。相对“m 天有效 n 天”指领券后第 m 天 `00:00:00` 起可用，至第 `m+n-1` 天 `23:59:59` 结束；相对小时有效期精确到分钟。 |
| 3 | 发券数量 | 本优惠券活动的申请总量，即最多可发放张数上限。 |
| 4 | 用券渠道 | 优惠券的特殊使用渠道：京东商城为主站销售场；拍拍二手为严选 App 和严选小程序渠道。 |
| 5 / 8 | 单次发放到账张数 | 用户一次领取或一次发放行为时，同时到账的优惠券数量；例如设置为 2，用户领取 1 次到账 2 张。截图中该字段重复出现。 |
| 6 | 非公开推广 | 原“免费领取”。生成配置 KEY 和领券链接，可按业务场景投放。 |
| 7 | 公开自动推广 | 配置后自动同步至选择的商详、购物车、领券中心、公开券池等渠道展示。全网推广会覆盖所有公开流量、券量可能消耗快；可选单品购物车、领券中心、公开券池等具体渠道。 |
| 9 | 每日领取次数 | 优惠券每天支持领取的最大次数（不等于时段发放张数）。例如每日领取 500 次、单次到账 2 张，则最高支持 500 次用户领取，共发放 1,000 张。时段发放张数 = 时段领取次数 × 单次发放张数。 |
| 10 | 用户领券规则 | 可设置活动期间仅可领一次或活动期间每天可领一次，约束单用户在活动期或每日的最大领取次数。 |
| 11 | 个人最大兑换次数 | 活动期间每个用户可兑换的最大次数。即使获得多个兑换码，仍受此上限约束。 |
| 12 | 兑换类型 | 兑换码或兑换链接。一个码/链接仅支持兑换一次；例如申请 200 张、单次到账 1 张，将生成 200 个兑换码。兑换链接可直接领取，也可转为二维码供线下扫码。 |

## 5. 系统校验与生成要求

### 5.1 模板选择与生成

1. 业务员选择“券活动类型、用户范围、优惠方式、用券渠道”后，系统自动锁定模板版本、叠加层和适用时间窗。
2. 系统按模板生成配券表，保留工作表名、表头、格式、数据验证和公式；生成文件中必须删除演示行或明确标记为不可提交。
3. 一份 OA 可含多个批次行，但每行必须独立校验，且每一行只对应一个渠道和一个将来回填的批次 ID。
4. 大促神券、PLUS、兑换券等固定标签应由系统预填并锁定，避免业务员选错模板后手改标签绕过规则。

### 5.2 提交前硬校验

- 同层券叠加校验；
- 模板与券活动类型、用户范围、优惠方式匹配；
- 大促神券是否处于已配置的大促开门红/高峰期；
- 用券渠道单值校验；
- 数量、金额、比例、折扣精度和日期合法性校验；
- 可领时间不晚于可用时间，且满足 OA 提报的提前工作日要求；
- 所有公式字段已计算且无除零、负值、超精度或公式被覆盖；
- 兑换类型、个人最大兑换次数与兑换券模板匹配；
- 商品白/黑名单须为单列商家 ID、SKU 或 SPU；校验 SKU/SPU 不混用、商家 ID 建券时仅可搭配其中一种 SKU/SPU 黑名单，以及质检优品、业务模式和大促神券限制（依赖商品主数据）。

### 5.3 回传复核

券生效后，由配券方回填活动 ID、批次 ID、`putKey` 及 PC/M 端领券链接。系统应自动对比“申请版本—实际回传版本”，重点核验活动名称、渠道、可领/可用时间、数量、优惠力度、适用商品及特殊标签，并记录差异与人工确认结论。

### 6.1 标准模板（应纳入模板版本库）

`配券信息表-常规满减券.xlsx`、`配券信息表-常规折扣券.xlsx`、`配券信息表-PLUS满减券.xlsx`、`配券信息表-PLUS折扣券.xlsx`、`配券信息表-兑换满减券.xlsx`、`配券信息表-兑换码折扣券.xlsx`、`配券信息表-大促神券常规满减券.xlsx`、`配券信息表-大促神券常规折扣券.xlsx`、`配券信息表-大促神券PLUS满减券.xlsx`、`配券信息表-大促神券PLUS折扣券.xlsx`。

2. 所有未给出枚举的字段（优惠券类型、限品类型、风控、用户领券规则、赠送、推广途径、公开推广渠道）的合法选项、默认值和组合限制。
3. 店铺券/店铺商品券是否完全不进入 OA 提报；如仍需记录，所需字段和审批边界是什么。

5. Excel 模板的正式版本号、维护人、变更审批方式和兼容策略；当前文件名未体现统一版本号。
6. 配券人实际回填的系统入口、回填时点、责任人及回传数据是否可通过接口自动获取。
