## 1. 场景与范围

优惠券提报是 OA 提报中的一个业务板块，覆盖两类申请：

- **优惠券申请**：为活动新建优惠券配置；
- **优惠券修改**：对已提交的优惠券申请/批次进行变更。

当前截图说明，优惠券申请及修改通过**飞书审批（OA）**发起。后续智能提报流程应以“收集信息、校验、生成并写入 OA 提单、生成邮件草稿、由业务员人工发送”为边界；不应自动通过审批或自动发送邮件。

## 2. 业务管控规则

| 编号 | 规则 | 系统处理建议 |
| --- | --- | --- |
| R-01 | 已申请的优惠券邮件原则上不允许修改；极特殊情况须领导特批。（标注：0624 更新） | 修改类型申请必须展示风险提示；是否允许继续、特批人及特批凭据须由业务确认后配置。 |
| R-02 | 优惠券申请须在券生效时间前至少 **2 个工作日**发起；申请后须关注审批是否完成，超时不予配置。（标注：0624 更新） | 按工作日历计算最晚发起时间；不满足时阻断提交或进入人工特批流程。审批超时应提醒申请人和配置负责人。 |
| R-03 | 因商家漏报、超时提报等原因，一律不支持补录。 | 在超期/补录场景提示不可补录；例外机制待确认。 |
| R-04 | 商家承担比例大于等于 50% 时，由商家自主提报配置；不支持口头约定后预先代为安排商家提报。（标注：0801 更新） | 当商家承担比例 ≥50% 时，提示或阻断运营代提，输出商家自主提报指引；准确的身份识别与例外规则待确认。 |
| R-05 | 受京东管控的大促神券仅可在营销规定的大促开门红或高峰期使用；常规日期使用须先联系王园园沟通。（标注：0801 更新） | 需维护大促时间窗与“受京东管控大促神券”标识；窗口外提交时要求人工确认/审批依据。 |
| R-06 | 质检优品因系统限制不支持配置大促神券；寄卖默认不配置大促神券；POP 大促如需配置，须先剔除质检优品。（标注：0801 更新） | 校验业务模式、券类型和商品名单；发现质检优品时阻断或提示先剔除。寄卖模式默认不允许大促神券。 |

### 2.1 时效规则示例（按截图原文）

券于 9 日生效：若 7 日为工作日，至少需在 7 日发起申请；若 7 日为休息日（如周日），则向前追溯 2 个工作日，至少于 4 日发起申请。

> **待确认**：截图中的示例与“生效前 2 个工作日”的精确计数口径可能存在歧义。PRD 应明确是否包含发起日、节假日数据来源、截单时刻、跨月/跨年规则及审批未完成时的处理方式。

## 3. OA 字段与条件规则

### 3.1 通用字段

| 字段 | 必填性 | 类型/可选值 | 规则与说明 |
| --- | --- | --- | --- |
| 申请类型 | 必填 | 选项：优惠券申请、优惠券修改 | 决定后续条件字段和流程分支。 |
| 业务模式 | 必填 | 选项：严选、寄卖、POP | 应作为商品、券类型和配置规则的关键判断条件。 |
| 活动名称 | 必填 | 单行文本 | 可填写时间、品类等，例如“0801-0804 苹果手机月初补贴”；与申请类型合并同步至审批标题。 |
| 配置渠道 | 必填 | 多选：京东渠道、严选 App 及小程序 | 可多选。 |
| 是否可叠加 | 必填 | 是、否 | 仅大促期间 POP 模式可选；截图另称 12 月份后受平台管控的券不可叠加。精确生效日期与适用券范围待确认。 |

### 3.2 “优惠券申请”条件字段

| 字段 | 必填性 | 类型 | 规则与说明 |
| --- | --- | --- | --- |
| 活动背景 | 条件必填 | 多行文本 | 填写活动背景、申请原因等。 |
| 活动点位 | 条件非必填 | 数字 | 填写优惠比例。字段含义及取值范围待确认。 |
| 平台承担比例 | 条件非必填 | 数字 | 填写平台承担比例；与商家承担比例、超扣点规则存在关联。 |
| 是否超扣点 | 条件必填 | 是、否 | 超扣点指平台承担的优惠比例是否超过佣金比例。 |
| 超扣点原因 | 条件必填 | 多行文本 | 当“是否超扣点”为“是”时应必填；截图未明确此触发条件，待确认。 |
| 预估 GMV | 条件必填 | 金额 | 填写预估活动可带来的 GMV。 |
| 预估费用 | 条件必填 | 金额 | 填写预估活动消耗的费用。 |
| ROI | 条件必填/自动生成 | 计算公式 | 系统自动计算：预估 GMV ÷ 预估费用。需明确费用为 0、空值、币种和精度的处理。 |
| 活动开始时间 | 条件必填 | 日期 | 用于时效校验。 |
| 活动结束时间 | 条件必填 | 日期 | 应校验不早于开始时间。 |
| 具体满减测算图片 | 条件必填 | 图片 | 上传具体满减测算截图，供各审批环节审核。 |
| 配券信息表 | 条件必填 | 附件 | 必须使用指定模板填写并保证信息准确。 |
| 商品明细白名单 | 条件必填 | 附件 | 指定优惠券生效对象；必须为单列“商家 ID”或“SKU”或“SPU”，且每个单元格仅一个值。 |
| 商品明细黑名单 | 条件非必填 | 附件 | 指定优惠券不生效/须剔除对象；格式同白名单：单列商家 ID、SKU 或 SPU，且每格仅一个值。 |

### 3.3 “优惠券修改”条件字段

| 字段 | 必填性 | 类型 | 规则与说明 |
| --- | --- | --- | --- |
| 修改原因及修改项描述 | 条件必填 | 多行文本 | 填写修改原因及拟修改内容。 |
| 关联优惠券申请审批 | 条件必填 | 关联审批 | 选择本次修改对应的原优惠券申请审批流。 |
| 涉及修改的批次 ID | 条件必填 | 多行文本 | 填写需修改的批次 ID。应明确多个批次的分隔及校验规则。 |
| 修改明细 | 条件必填 | 附件 | 上传修改明细表，可包括配券信息表、商品明细白名单、商品明细黑名单等。 |

## 4. 表单动态交互与校验顺序

1. 业务员选择申请类型和业务模式；系统加载对应分支字段与规则。
2. 业务员录入通用信息；选择“优惠券申请”时展示活动、费用、时间和附件字段，选择“优惠券修改”时展示原审批、批次及修改明细字段。
3. 业务员上传附件后，系统校验模板、列名、单列要求、单元格值数量及白黑名单重复项；商品属性校验（例如质检优品）应基于可用商品主数据进行。
4. 系统执行字段必填、数值范围、ROI、活动日期、工作日提前期、业务模式/券类型/叠加规则、商家承担比例和大促时间窗校验。
5. 校验通过后生成 OA 审批标题、表单数据和邮件草稿；存在可特批异常时输出异常清单与补充材料要求，不可静默绕过规则。
6. 表格/OA 写入成功后，通知业务员复核；邮件仅保存草稿，业务员在邮箱中确认内容后手动发送。

## 5. 初步数据与功能需求

- 管理员可维护字段定义、必填条件、选项值、公式、附件模板、工作日历、大促窗口、券类型规则和例外审批规则，并以版本发布。
- 每次提报应固化申请人、提交时间、模板版本、原始字段、附件版本、校验结果、异常/特批依据、OA 单号或链接、邮件草稿状态及最终人工发送状态。
- 对修改申请，应保留原申请与修改申请的关联关系、修改前后字段差异及涉及批次。
- 系统应将“硬阻断”“允许提交但需人工确认”“仅提示”三类校验结果明确区分；各规则的最终等级由业务 Owner 确认。

## 6. 待业务确认清单

1. “已申请优惠券邮件不允许修改”与 OA 中“优惠券修改”流程的适用边界、可修改字段、领导特批路径及证据要求。
2. “生效前 2 个工作日”的准确计算方式、节假日历来源、每日截单时间及审批超时后的责任与处理方式。
3. “活动点位”、严选、平台承担比例、商家承担比例、佣金比例及超扣点之间的精确定义、数据来源和计算公式。
4. 商家承担比例 ≥50% 时，系统是完全阻断运营代提、转交商家发起，还是允许特批；如何识别商家自主提报身份。
5. 大促神券、受京东管控券及普通券的分类数据来源；大促开门红/高峰期时间窗的维护人和审批例外方式。
6. 质检优品的识别数据源、POP 剔除规则，以及寄卖是否存在经批准的例外。
7. 配券信息表、白名单、黑名单的真实模板文件、允许的文件格式/最大大小、去重规则及商品 ID 的跨列/跨文件冲突处理。
8. OA 表单、业务底稿、邮件草稿三者分别由哪个系统承载和写入；“OA 邮件”与飞书 OA 审批的关系、收件人/抄送人规则及邮件草稿接口可用性。
