# 动态多 Sheet 商品名单设计

> 日期：2026-10-13  
> 状态：待需求方审阅  
> 范围：三源优惠券 P0 的商品白名单与可选黑名单识别、确认和标准附件生成

## 1. 目标

三源提报必须接受业务上传的任意有效券档 Sheet，而不是把商品名单限制为仓库内登记的五个固定 Sheet。系统应逐 Sheet 识别 SKU 列，把每页与本次配券表识别出的券档建立可审计关联；无法唯一关联的项目合并进入一次第二轮中文确认。确认后生成受控标准名单附件。

成功标准：

- `100减1`、`2000减20`、`3000减30`、`3000减60` 等未预登记 Sheet 不再仅因名称不同而失败；
- 输出保留有效源 Sheet 的名称、相对顺序和 SKU 行顺序；
- 每个输出 Sheet 只有一列标准表头 `sku`，不复制源表其他列、公式、样式或说明文字；
- AI 是首要候选识别器，确定性服务端验证证据和业务约束；
- 低置信度、冲突或多义关联只产生一轮中文业务确认，不暴露坐标和内部字段名；
- 源名单仍不会直接成为 OA 附件，只有确认后生成并校验的标准名单可进入测试稿路径。

## 2. 非目标与安全边界

- 不允许 AI 决定权限、审批结果、OA 路由或是否创建原生 OA。
- 不把 Sheet 在工作簿中的位置当作券档事实，禁止按数组下标静默配对。
- 不复制宏、公式、外链、隐藏对象、图片或任意源格式到标准附件。
- 不扩大当前支持的名单维度；P0 仍只接受 SKU。
- 不改变白黑名单交集的显式决策规则。
- 不放宽单元格公式注入、数值型 SKU、前导零、重复值和最大行数校验。

## 3. 当前根因

当前解析类型、生成 manifest 和验证器共享 `MultiTierSkuSheetName`，其值固定为五个 Sheet 名。AI 已识别出的 `tierDisplayName` 和实际 Sheet 名仍会经过该固定集合转换；转换失败即返回“无法唯一对应已登记券档”。后续生成器又按固定 manifest 创建五页，因此仅修改 AI prompt 无法解决问题。

本次必须同时解除三处耦合：领域类型、识别/确认模型、标准附件生成器。

## 4. 领域模型

新增动态名单 Sheet 合同：

```ts
interface DynamicSkuListSheet {
  sourceSheetName: string;
  sourceSheetIndex: number;
  outputSheetName: string;
  dimension: "SKU";
  entries: SkuListEntry[];
  couponTierMatch:
    | { status: "matched"; couponTierId: string; confidence: number }
    | { status: "needs_confirmation"; candidateTierIds: string[] }
    | { status: "unmatched" };
  evidence: {
    headerCell: string;
    region: { startCell: string; endCell: string };
  };
}
```

`couponTierId` 是当前 revision 内根据配券表识别结果生成的稳定内部标识，不依赖全局券档字典，也不直接使用展示文案充当主键。Sheet 展示名称和券档展示名称分别保存。

规范化包使用 `whitelistSheets` 和可选 `blacklistSheets`，不再使用固定键的 `Record<MultiTierSkuSheetName, string[]>`。每个条目继续保存来源文件 hash、Sheet、单元格、原始值和标准化值。

## 5. 识别与关联

### 5.1 AI-primary

DeepSeek 对每个 Sheet 返回：SKU 表头、数据区域、维度、券档展示候选、候选依据和置信度。服务端必须验证：

- Sheet 和证据坐标确实存在；
- 表头列位于证据区域内；
- 数据单元格是文本，不是公式或数值型 SKU；
- 每格只有一个 SKU；
- SKU 不为空且符合现有长度和字符约束；
- AI 给出的券档候选存在于同一 revision 的配券表识别结果。

AI 失败或输出无效时，现有规则识别只用于找 SKU 列和提供候选，不恢复固定五档限制。

### 5.2 唯一关联

系统可在以下条件下自动建立关联：AI 候选通过证据校验，且在当前配券表券档中唯一；或标准化后的 Sheet 名与唯一券档展示名精确一致。相似度只能用于候选排序，不能独自形成事实。

以下情况进入第二轮：

- 一个 Sheet 对应多个合理券档；
- 多个 Sheet 竞争同一个不允许复用的券档；
- AI 券档候选不存在于本次配券表；
- Sheet 名和内容无法提供唯一关联。

第二轮以中文展示 Sheet 名、SKU 数量和券档候选，例如“白名单页‘3000减60’对应哪一档优惠券？”。一次卡片收集全部歧义，不逐 Sheet 追加消息。

### 5.3 多 Sheet 券档关系

一个工作簿可以有任意数量的有效名单 Sheet。P0 默认一个 Sheet 关联一个券档；一个券档如需对应多个 Sheet，必须由业务员明确确认，输出仍保留多个 Sheet，不自动合并。跨 Sheet 重复 SKU 延续当前阻断规则，避免同一 SKU 被不同券档同时纳入；若业务确实允许，需另行产品决策。

## 6. 标准附件生成

新增动态名单生成器，不再读取固定五 Sheet 模板：

1. 创建空白 `.xlsx`；
2. 按 `sourceSheetIndex` 生成工作表；
3. 对 Sheet 名执行 Excel 合法性校验；重名或规范化冲突进入确认，不静默改名；
4. `A1` 固定写入 `sku`；
5. 从 `A2` 起按源行顺序写入文本 SKU，单元格格式固定为文本；
6. 不复制任何其他列、公式、合并单元格、隐藏状态或工作簿关系；
7. 重新打开生成文件并验证 Sheet 名称、顺序、每页条目、文本格式、总行数和 SHA-256。

产物审计摘要记录每页 Sheet 名、券档内部 ID、行数和 hash，不记录完整 SKU。

## 7. 白名单与黑名单

白名单和黑名单复用同一动态 Sheet 合同与生成器。只有双方均完成 SKU 维度和券档关联确认后才计算交集。交集计算以 SKU 为主，并记录所在 Sheet；现有白名单优先、黑名单优先或重新上传三种显式选择保持不变。

未上传黑名单仍必须明确确认“本次无黑名单”。

## 8. 兼容和迁移

- 固定五档工作簿继续正常识别，但仅作为普通动态 Sheet，不再享有硬编码类型地位。
- 单券档名单走同一动态结构，只包含一个 Sheet。
- 已生成的历史 revision 和附件不可重写；新模型只用于新 revision。
- 卡片 action 必须绑定当前 revision 和候选 hash，源文件变化后旧确认失效。
- 模板 ID 需要新增动态名单版本，旧固定 manifest 保留给历史校验，不再用于新产物。

## 9. 错误处理

以下问题阻断生成并提供中文修复提示：无可用 SKU、数值型 SKU 无法证明前导零、公式/注入前缀、非法或重复 Sheet 名、单格多个 SKU、跨 Sheet 重复、证据坐标失效、确认引用旧 revision。

DeepSeek 超时或失败不返回成功状态。规则降级可以继续找候选；不能确定时统一进入第二轮，不能伪造关联。

## 10. 测试与验收

本地 fixture 至少覆盖：

- 截图中的四个自由券档 Sheet；
- 固定五档兼容；
- 单 Sheet 与十个 Sheet；
- 中英文、金额格式差异及合法 Excel Sheet 名边界；
- AI 正确、AI 低置信度、AI 坐标伪造、AI 券档不存在、AI 超时；
- SKU 前导零、公式、数值单元格、重复值、空页和超限；
- 白黑名单交集及显式决策；
- 生成后回读的 Sheet 名、顺序、SKU、文本格式和 hash；
- 重复事件、重复点击、旧卡和 revision 变化不会重复生成或接受旧确认。

飞书 E2E 只在本地测试、类型检查、构建和受保护 Preview 身份回读全部通过后进行。成功终点仍为隔离 OA 测试稿；不得创建原生 OA。
